# Архитектура

## Назначение и ограничения
Выделенный CPU-сервер в доверенной LAN выставляет тяжёлые ML-модели через единый RPC-транспорт RPyC (порт 18812). Без REST, без аутентификации, без TLS: граница доверия — частная сеть без пробросов портов извне. Бизнес-пайплайны строятся на стороне клиента.

## Компоненты
- rpc/server.py — транспорт и фасад: exposed-методы, валидация всех входов до записи на диск, исполнение job-ов, сериализация (Semaphore(1)), очистка каталогов job-ов при старте.
- rpc/registry.py + models.manifest.toml — реестр моделей: имя, RPC-метод, путь cli, интерпретатор venv, timeout.
- models/<имя>/ — каталог модели: cli (тонкая трансляция API модели), install.sh (идемпотентная установка весов и зависимостей), pyproject.toml + uv.lock (изолированный venv), weights/ (вне git), README.md (контракт метода).
- bootstrap.sh — идемпотентная установка сервера из-под root: apt, uv 0.12.0, install.sh каждой модели, systemd unit, права.
- deploy/inference-server.service.in — unit: non-root пользователь, песочница (ProtectSystem=strict, пустой CapabilityBoundingSet, NoNewPrivileges, PrivateTmp), офлайн-окружение (HF_HUB_OFFLINE=1, TRANSFORMERS_OFFLINE=1).

## Поток вызова
Клиент (rpyc версии сервера) → exposed-метод → валидация типов и границ → JOB_SLOT → uuid4-каталоги rpc/data/in|out → subprocess (cli модели в её venv, без shell, start_new_session) → timeout из манифеста (SIGKILL группе процессов) → чтение выходного файла → bytes клиенту → удаление каталогов job-а в finally.

## Принципы контракта
- cli модели — тонкая трансляция API модели: только проброс параметров, никакой собственной логики.
- По RPC передаются только примитивы: bytes, str, int, float, bool, list, None. pickle и доступ к атрибутам отключены protocol_config.
- Непримитивные параметры моделей не выставляются; эквиваленты и причины — в README модели.
- Контракт модели документируется в models/<имя>/README.md; общий README контрактов моделей не содержит — удаление модели не требует правки общих документов.
- API модели проверяется inspect.signature по установленной версии до написания cli; интернет-документация других версий вторична.

## Безопасность
Код и конфигурация принадлежат root (r--r--r--), сервис читает без права записи; запись — только rpc/data и приватный /tmp. HF-токен (Read) передаётся только в env установки, на диске не хранится; в рантайме доступ к HF закрыт офлайн-переменными — все веса и кэши скачиваются и прогреваются на установке.

## Добавление модели
1. models/<имя>/: pyproject.toml + uv.lock, install.sh (веса, кэши, smoke), cli (трансляция API), README.md (контракт).
2. models.manifest.toml: имя, метод, cli, python, timeout_seconds.
3. rpc/server.py: exposed-метод, валидация всех входов до записи на диск.
4. Установка: bootstrap.sh (идемпотентен).
5. Тесты: позитивные, границы, негативные, детерминизм (если модель его даёт).
6. Фиксация в репозитории только после зелёных тестов.

## Удаление модели
1. Удалить models/<имя>/ — документация модели удаляется вместе с каталогом.
2. Удалить запись из models.manifest.toml.
3. Удалить exposed-метод из rpc/server.py.

## Подводные камни (проверено на этом проекте)
- ai-edge-litert и ai-edge-litert-nightly занимают один import-путь: переустановка только с --reinstall-package, контроль — функциональным импортом, а не метаданными.
- xnnpack-кэш fp32 TFLite-моделей строится только nightly litert; прогрев кэшей — короткие генерации на установке.
- Gated-модели (pyannote/speaker-diarization-community-1) требуют принятия лицензий аккаунтом HF до установки; токена Read без принятия недостаточно.
- Внутренний sudo -u обрезает окружение: HF_TOKEN пробрасывается явно.
- normalize_text у OmniVoice требует WeTextProcessing (модуль tn) — объявляется в pyproject модели.
- kwargs библиотек сверяются с установленной версией: параметр из документации другой версии ломает весь метод (initial_prompt в whisperx 3.8.6).
- Повторный запуск установки обязан быть идемпотентным: официальные установщики перетирают закреплённые версии (ai-edge-litert поверх nightly).
