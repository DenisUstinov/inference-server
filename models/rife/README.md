# RIFE (interpolate_video)

Модель: rife-ncnn-vulkan, сборка 20221029 (nihui), Vulkan/ncnn; исполнение на CPU через Mesa lavapipe (официально совместимая реализация Vulkan 1.3). Алгоритм: RIFE — Real-Time Intermediate Flow Estimation (arXiv 2011.06294, ECCV 2022). Выход: MP4 (libx264, yuv420p), звуковая дорожка копируется из источника, выходной fps = fps источника × multiplier.

## RPC-метод

    interpolate_video(video, multiplier=2, model='rife-v4.6', uhd=False,
                      tta_spatial=False, tta_temporal=False,
                      jobs=None, gpu_id=None) -> bytes MP4

## Параметры и границы (валидация на сервере до записи на диск)
- multiplier 2..8 — целевое число кадров = кадры источника × multiplier. Ограничение бинарника: произвольное число кадров поддерживает только семейство rife-v4 («only rife-v4 model support custom numframe and timestep»); для остальных 9 моделей доступен только режим 2× (дефолт бинарника N*2), комбинация multiplier != 2 с не-v4 моделью отклоняется ValueError до запуска job-а.
- model — 11 моделей поставки 20221029: rife, rife-HD, rife-UHD, rife-anime, rife-v2, rife-v2.3, rife-v2.4, rife-v3.0, rife-v3.1, rife-v4, rife-v4.6 (дефолт). Наличие каталога модели проверяется cli; имена с '/' или '..' отклоняются ValueError (защита от path traversal).
- uhd — режим -u: оптический поток оценивается на уменьшенном изображении и переносится на исходное разрешение (назначение — 4K+).
- tta_spatial (-x), tta_temporal (-z) — Test-Time Augmentation: повышение качества ценой скорости; по issue #64 совместное включение даёт лучший результат.
- jobs — строка 'load:proc:save' (флаг -j, дефолт бинарника 1:2:2; рекомендация README: 4:4:4 для множества мелких кадров, 2:2:2 для крупных). Валидация: ровно три положительных целых через двоичие. На результат не влияет (измерено), влияет на скорость.
- gpu_id — флаг -g: -1 = CPU, 0..N = индекс Vulkan-устройства. Валидация: >= -1. Сервер без GPU — фактическое исполнение lavapipe.

## Исключения (не выставляется через RPC)
- -s time-step — применим только к попарному режиму -0/-1 (интерполяция между двумя кадрами); контракт работает с видео через -n/дефолт.
- -0/-1 — режим двух изображений, вне видео-контракта.
- -f pattern-format, -v verbose — внутренние параметры job-а (именование промежуточных файлов, лог).

## Известные факты (измерено)
- Детерминизм: одинаковые вход и параметры дают байт-идентичный MP4 (uhd-регрессия 7990 байт воспроизведена多次кратно).
- Размеры выхода на тесте 320×240/12fps/1с: uhd 7990, anime 9095, v2.3 9641, v4 x4 9586, v4.6 x8 11157 — различия по моделям нормальны.
- Кадры декодируются ffmpeg в PNG, интерполяция, обратная сборка libx264 с fps×multiplier; VFR-источники берут базовую частоту r_frame_rate.

## Измерения (4 CPU, lavapipe)
Тестовый клип 1 с: ~10–30 с на job в зависимости от модели и режимов; UHD/TTA увеличивают время. Timeout манифеста 7200 с.
